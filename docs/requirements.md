## 1. 背景与问题

我在日常工作中反复遇到四个问题，它们互相加剧：

| # | 问题 | 具体表现 |
| --- | --- | --- |
| P1 | **想法记不下来** | 正在做 A 时被口头交代 B，或突然想到 C；打开待办软件、选清单、填字段、保存——步骤太多，于是先记在纸上/脑子里，然后就丢了 |
| P2 | **清单只会堆积** | 攒了几十条"要做的事"，但都停在一句话粒度，不知道从哪下手，看不清"今天做什么" |
| P3 | **跟进靠回忆** | 一件事推进了三次，中间结论散在聊天记录、便签、脑子里的临时记忆；再捡起来要重新推理一遍 |
| P4 | **复盘是编的** | 写日报/周报时想不起这周干了什么，只能凭印象凑，过程细节全丢了 |

**根因判断**：不是我懒，而是现有工具把「记录」和「结构化」这两件成本完全不同的事**压在同一个动作里完成**——想快速记，就得先想清楚它属于哪个项目、什么优先级、什么时候做。这一步的摩擦力，就是所有记录习惯死掉的地方。

## 2. 目标与非目标

### 2.1 目标

**一句话目标**：做一个常驻 Windows 桌面的个人工作秘书，让我能在**不打断当前工作**的前提下把任何东西丢进去，然后由它（必要时借 AI）帮我把混乱的输入整理成可执行、可跟进、可复盘的结构。

拆成三条可验证的目标：

- **G1 · 零摩擦捕获**：任何念头，从"意识到要记"到"记完并回到工作"，**不超过 3 秒、不切换窗口、不选分类**。
- **G2 · 结构化兜底**：堆积的收件箱能通过一次操作（AI 拆分 + 我确认）变成有层级、有验收标准、有排期的任务树，而不是靠我逐条手工整理。
- **G3 · 记录即资产**：每次推进的备注和每日日志天然沉淀为单一事实源，写日报/周报时是**导出**而不是**回忆**。

### 2.2 非目标（明确不做，防止范围失控）

| 不做 | 原因 |
| --- | --- |
| 多人协作 / 任务分派 / 权限 | 只服务我一个人，引入账号与并发会拖垮体验 |
| 手机端 / 多设备同步 | v1 单机；同步会带来冲突合并、鉴权、部署一整套复杂度 |
| 习惯打卡、番茄钟、时间统计 | 本次明确不需要（无计时、无精力/情绪记录） |
| 云账号与 SaaS 登录 | 数据主权是选它的理由之一，不想被订阅和隐私条款绑架 |
| AI 全自动接管我的任务表 | 明确选择"按需调用 + 人工确认"，避免不可信自动化带来的失控感 |
| 通用笔记系统 / 知识库 | 只做"与工作和任务有关的记录"，不做第二大脑 |

## 3. 使用者与使用场景

### 3.1 使用者

只有一个人：需要同时推进多件事、频繁被打断、且需要向上汇报进展的知识工作者。环境为 Windows 单机，数据不离开本机（AI 拆分时按需发送最小片段）。

### 3.2 三个核心场景

**S1 · 随手一记（每天 10–30 次）**
> 正在写代码，同事过来说"下周三之前把接口文档给一下"。
> 按 `Ctrl+Alt+Space` → 输入框已聚焦 → 敲"接口文档 下周三 给张三" → `Enter`。窗口消失，人没离开键盘。

**S2 · 每日定盘（每天 1 次，约 5 分钟）**
> 打开收件箱，看到一天攒下的 8 条碎片。选中其中 3 条点「AI 拆分」，弹出可编辑的子任务预览：包含步骤、验收标准、建议排期。删掉两条不认可的，确认写入。把剩下 2 条拖进已有项目，3 条直接归档（其实是垃圾）。

**S3 · 推进与复盘（随时 + 每天下班前）**
> 任务推进到一半卡住了：在悬浮小组件里点开那条任务 → 追加一句"卡在等法务确认，已催"。
> 下班前弹提醒，打开当日日志：已完成 4 条、新增 3 条、顺延 2 条、卡点 1 条已自动汇总好，我补两句说明，保存。

## 4. 核心概念模型

只保留六个概念，全部围绕"从混乱到有序"的流水线设计：

```
【捕获】收件箱 Inbox ──分类──> 【结构】项目 → 任务 → 子任务（三级树）
                  │                        │
                  │                        ├── 进展记录 ProgressEntry（每次推进一条，带时间戳）
                  └──归档──> 资料条目       │
                             ArchiveItem ───┘
                                    │
                              ──汇总──> 每日日志 DailyLog（自动汇总 + 人工补录）
                                              │
                                        ──> Markdown 导出（日报 / 周报）
```

| 概念 | 定义 | 关键属性 |
| --- | --- | --- |
| **收件箱 Inbox** | 一切未分类输入的默认落点。**唯一要求是"必须能被清空"** | 原始文本、创建时间、可选标记（待办 / 资料） |
| **项目 Project** | 一件事、一个阶段或一条工作线（如"Q3 数据平台迁移"） | 名称、状态、起止、目标描述、进度（由任务汇总） |
| **任务 Task** | 可独立交付、有明确完成判据的工作单元 | 标题、状态、优先级、截止时间、预估、所属项目、来源 |
| **子任务 Subtask** | 任务下的可执行步骤 | 标题、状态、顺序、（可选）截止时间 |
| **进展记录 ProgressEntry** | 挂在项目/任务/子任务任意一层上的带时间戳备注 | 内容、时间、类型（进展 / 卡点 / 决定 / 等待他人） |
| **每日日志 DailyLog** | 一天的收口，系统自动汇总 + 我手工补录 | 当日完成、新增、顺延、卡点、明日计划、自由正文 |
| **资料条目 ArchiveItem** | 与工作相关的非任务信息：会议纪要、链接、截图、文件 | 正文、附件、关联对象、来源 |

**对象关系**：一个项目包含多个任务；一个任务包含多个子任务；任意层级都可挂进展记录；每日日志通过时间维度聚合所有对象；资料条目可关联到任意对象（也可游离）。

**状态机（最小集）**：
- 任务：`待办 → 进行中 → 阻塞 → 完成 / 取消`（`阻塞` 必须能填原因，这是 S3 的关键）
- 子任务：`待办 → 完成`
- 收件箱：`未处理 → 已分类 / 已归档`

## 5. 功能需求

优先级定义：**P0 = v1 必须有**，缺了就不算可用；**P1 = v1 应有**；**P2 = 后续迭代**。

### 5.1 P0 — 捕获层

| 编号 | 功能 | 设计要点 | 验收标准 |
| --- | --- | --- | --- |
| F-01 | **快记浮窗** | 全局快捷键 `Ctrl+Alt+Space` 唤出无边框小窗，输入框自动聚焦 | 按下热键到可输入 **≤ 150ms**；`Enter` 保存并关闭，`Shift+Enter` 换行，`Esc` 取消不留痕 |
| F-02 | **一键式快速分类** | 输入框下三个芯片：`收件箱`(默认) / `进展` / `资料`；**不做二级选择、不弹出项目选择器**，保持肌肉记忆 | 从输入到入库 ≤ 2 次按键 |
| F-03 | **无干扰反馈** | 保存后不弹确认框，仅在浮窗位置播放 300ms 的收起动画 + 可选轻提示音 | 不抢焦点、不打断当前窗口输入 |
| F-04 | **收件箱视图** | 列表 + 一键清空流程：每条可 `转任务 / 立项 / 并入已有 / 归档 / 删除`，支持多选批量操作 | 20 条收件箱可在 5 分钟内处理完 |
| F-05 | **全局快捷键** | 可在设置中自定义，检测冲突并提示 | 冲突时给出明确提示而非静默失效 |

### 5.2 P0 — 结构层

| 编号 | 功能 | 设计要点 | 验收标准 |
| --- | --- | --- | --- |
| F-06 | **三级任务树** | 项目 → 任务 → 子任务；树内拖拽可改层级与顺序 | 拖拽排序、跨项目移动不丢进展记录 |
| F-07 | **任务详情编辑** | 标题、状态、优先级、截止时间、预估时长、标签、备注 | 键盘可完成全部编辑（不强制用鼠标） |
| F-08 | **今天是哪些** | 一个聚合视图：今日到期 + 手动加入今日 + 阻塞项置顶 | 打开即可回答"我现在该做什么" |
| F-09 | **进展记录** | 在任意层级选中后 `Ctrl+Enter` 追加一条带时间戳的记录，类型可选（进展/卡点/决定/等待他人） | 追加动作 **≤ 2 秒**，写完后任务状态可一键联动（如加"卡点"自动转 `阻塞`） |

| F-11 | **全局搜索** | 搜任务、子任务、进展记录、日志、资料全文 | 1000 条数据下结果 **≤ 200ms** |

| F-19 | **截止提醒（轻量）** | 任务到期或逾期时在悬浮组件内高亮，可选择性弹系统通知 | 提醒不重复轰炸（同一任务每天最多 1 次） |
| F-20 | **AI 任务拆分** | 选中收件箱条目或任务 → 「帮我拆」→ 调用云端 API → 弹出**可编辑预览**（子任务列表 + 验收标准 + 建议先后顺序）→ 我删改后确认 → 写入 | 预览中的每一项都可编辑/删除/合并；未点确认前**不写入任何数据**；可重试与换模型 |
| F-21 | **AI 配置** | 设置页填写 API 供应商 / Base URL / Key / 模型名；Key 用系统凭据或加密文件保存 | 支持 DeepSeek 与 OpenAI 兼容接口；调用前提示将发送哪些文本 |
| F-22 | **Markdown 导出** | 日报 / 周报 / 项目进展三种模板，一键复制到剪贴板或导出 `.md` 文件 | 输出可直接粘进聊天工具或邮件 |

## 6. 关键交互约定（UI/UX 契约）

这几条是产品的"手感"，实现时必须守：

1. **浮窗永远不抢主窗口焦点**：呼出快记后，原来的编辑器光标位置不丢。
2. **默认值必须正确**：不选分类就是收件箱，不选时间就是今天，不选优先级就是中。**永远不强迫我在记录时做决定。**
3. **不存在"保存失败"**：先落本地磁盘再处理业务；网络与 AI 全部是异步旁路，断网也能记。
4. **所有 AI 输出都是建议，不是命令**：预览 → 确认 → 写入，且写入后可整体撤销。
5. **收件箱可以长期不清空，但必须能一眼看到积压了多少**——用数字刺我，而不是用红色警告烦我。

## 7. 数据与技术方案（初稿，技术栈由我决策）

### 7.1 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 桌面外壳 | **Tauri 2** | 安装包约 10MB、常驻内存低，适合 7×24 挂托盘；原生支持托盘、全局快捷键、多窗口、开机自启 |
| 界面 | TypeScript + React + Vite | 生态成熟，浮窗/组件式 UI 开发快 |
| 本地存储 | **`node:sqlite`（Node 26 内置，WAL 模式）** | 已实测本机 `node:sqlite` 可用：**零原生编译依赖**，不装 `better-sqlite3` 也能用 SQLite + FTS5，避免 node-gyp/MSVC 带来的构建麻烦 |
| 数据目录 | **工程目录下 `data\`** | `data/workhelper.db` + `data/attachments/` + `data/backups/`；**必须写进 `.gitignore`**，避免数据被提交 |
| 数据可读性 | SQLite 为主 + **Markdown 导出** | 数据库保证查询性能，导出保证"哪天不用这个软件了，资料还在" |
| AI | **DeepSeek 官方 API**（OpenAI 兼容协议） | 已定；接口按 OpenAI 兼容层抽象，换供应商零成本 |
| 备份 | 启动时自动快照，保留最近 7 日 + 4 周 | 单机数据的唯一风险是硬盘和误删 |

### 7.2 架构原则：内核与界面分离

必须在第一行代码就成立的一条：**数据模型与业务逻辑不依赖桌面容器**。

```
┌─────────────────────────────────────────────┐
│  界面层（可替换）                             │
│  主窗口 / 快记浮窗 / 悬浮小组件 / 托盘菜单      │
└──────────────────┬──────────────────────────┘
                   │  本地 IPC（命令 + 事件）
┌──────────────────▼──────────────────────────┐
│  内核层 WorkHelper Core                      │
│  ┌─────────┬─────────┬──────────┬────────┐  │
│  │ 任务域   │ 日志域   │ 收件箱域  │ 搜索域  │  │
│  └─────────┴─────────┴──────────┴────────┘  │
│  Repository（唯一写入口）+ 事件总线            │
└──────────────────┬──────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │ SQLite + 附件目录     │
        └─────────────────────┘
                   ▲
                   │ 可选：CLI / MCP（P2）
```

好处很实际：将来想要"在 DSH 里也能登记任务"或"用命令行批量导入"，只需在内核上加一个适配层，不用重写业务逻辑。

## 8. 里程碑与验收指标

| 阶段 | 内容 | 完成判据 |
| --- | --- | --- |
| **M0 · 走通闭环** | 内核 + SQLite + 快记浮窗 + 收件箱 + 三级树 + 进展记录 | 我能连续 3 天真实使用它登记与推进，不丢数据 |
| **M1 · 常驻化** | 托盘 + 全局快捷键 + 悬浮小组件 + 开机自启 + 每日日志自动汇总 | 一周内不需要主动"想起要打开它"，随手记成为条件反射 |
| **M2 · AI 与复盘** | AI 拆分（预览确认）+ 每日提醒 + Markdown 导出 | 日报从"回忆 20 分钟"变成"导出 1 分钟" |
| **M3 · 打磨** | 性能、备份恢复、导入导出、P2 候选按需挑选 | 装机即可长期使用，无数据丢失事故 |

### 全局定量指标（写在验收清单里）

| 指标 | 目标值 |
| --- | --- |
| 快记浮窗呼出延迟 | ≤ 150ms |
| 快记端到端（热键 → 保存 → 窗口消失） | ≤ 500ms |
| 常驻内存占用（托盘 + 悬浮组件） | ≤ 100MB |
| 冷启动到可登记 | ≤ 2s |
| 搜索响应（1000 条数据） | ≤ 200ms |
| 数据可靠性 | 断电/强杀进程后无已提交记录丢失 |

## 11. 环境状态（已实测）

| 项 | 状态 | 说明 |
| --- | --- | --- |
| DSH 文件沙箱 | ✅ 已解决 | 原 `SetNamedSecurityInfoW failed (Win32 5)` 的成因：当前账户为 UAC 过滤令牌（`BUILTIN\Administrators = Group used for deny only`），沙箱无法修改工作区 DACL 来授予受限子进程写权限。会话切至 `danger-full-access` 后**完全绕过沙箱**，命令恢复正常 |
| Node.js | ✅ v26.10.0（`D:\AppGallery\node.exe`） | **`node:sqlite` 实测可用** → M0 不需要任何需本地编译的依赖 |
| WebView2 运行时 | ✅ 153.0.4234.48 | Tauri 渲染引擎已就位 |
| npm | ✅ 11.19.1 | pnpm 12.6.0 正在首次下载 |
| `git` / `python` / VS Code | ✅ 2.45.1 / 已装 / 已装 | — |
| **Rust 工具链** | ❌ **缺** | `rustup`/`cargo`/`rustc` 均无 → **M1（接桌面壳）前必须安装** |
| **MSVC 生成工具** | ❌ **缺** | 无 VS 2022 C++ 工具链，`rustc` 会报 `link.exe not found` → 与 Rust 同批安装 |
| PowerShell 执行策略 | ⚠️ 全 `Undefined`（等价 Restricted） | `npm.ps1` / `pnpm.ps1` 被拦截；解决：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

**结论：M0 无阻塞，可以立刻开工；Rust + MSVC 推迟到 M1 之前安装。**

## 附录 A · 调研结论对需求的影响

完整调研见 [已有方案调研与选型对比](research-existing-solutions.md)。直接影响本文档的三条结论：

1. **不存在现成方案可覆盖 70%**（调研结论 B）：开源侧缺"Windows 常驻捕获 + AI 拆解 + 本地事实源"三合一，因此自研核心，但采用 Backlog.md 式的「Markdown 导出 + 可选 Git」作为数据出口，避免把自己锁死。

3. **AI 自动排程不可信、引发失控感**（结论 A-3）：这印证了"AI 按需调用 + 预览确认"的选择，也把"全自动排期"明确排除在范围之外。
