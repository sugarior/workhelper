| 步 | 内容 | 里程碑 | 完成后你能做什么 |
| --- | --- | --- | --- |
| **A** | 本地 HTTP 服务 + 快记窗 + 四页签主界面 | M0 T8 | 用浏览器打开界面，鼠标/键盘完成全部操作 |
| **B** | 桌面壳（Tauri）：全局快捷键唤出快记、主窗口 | M1 前半 | **按一个键就能记，不用碰终端** |

## 3. 步 A · 页面（M0 T8）

**目标**：把已有的服务层接到界面上。内核一行不改——这是分层纪律的第一次真正检验。

### A1 本地 HTTP 服务（`src/ui/server.ts`）

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 监听 | **只绑 `127.0.0.1`**，默认端口 7317，可配置 | 设计 §7.1：不引入任何外部可达面 |
| 路由 | `GET /` 主界面；`GET /capture` 快记窗；`POST /api/<service>/<method>` 门面转发 | 设计 §7.1 |
| 实现 | `node:http` 手写，**不引入 Web 框架** | 零依赖约束 |
| 安全 | 只允许 `POST` 到白名单方法；拒绝路径穿越；请求体大小上限 | 本地服务也要有基本防线 |
| 生命周期 | 单实例：重复启动时检测端口占用并提示，而不是静默失败 | 避免多进程写同一个库 |

### A2 快记窗（`/capture`）— 最关键的一屏

这是**整个产品成败所系**的一屏，需求 §6 的五条交互契约全部落在这里：

| 契约 | 实现要求 |
| --- | --- |
| 浮窗不抢原窗口焦点 | 浏览器窗口下尽力而为；Tauri 阶段才真正成立（记入限制） |
| 默认值必须正确 | 输入框打开即聚焦；分类芯片默认选中「收件箱」，不选也能保存 |
| 不存在保存失败 | 保存失败时窗口**不关闭**，在输入框下方显示红字；不做弹窗 |
| 所有解析都是建议 | 识别到日期时在下方显示浅色标签 `截止 2026-10-07`，识别不到则**不显示任何元素** |
| 不阻断 | `Enter` 保存并关闭，`Shift+Enter` 换行，`Esc` 取消；`Tab` 可在三个芯片间移动 |

**验收**：从按键到界面可输入 ≤ 150ms；从 `Enter` 到窗口关闭 ≤ 500ms（需求 §8 指标）。

### A3 主界面四页签

| 页签 | 内容 | 对应需求 |
| --- | --- | --- |
| **收件箱** | 待处理列表（含解析出的截止日、原文折叠展示）+ 多选 + `转任务 / 归档 / 丢弃` + **撤销按钮**（有无可撤销由 `canUndoClassification` 决定）+ 顶部待处理计数 | F-04、需求 §6.5 |
| **今日** | 逾期（红）/ 今日到期 / 手工加入 / 阻塞 四组；每条可展开追加进展；卡点用醒目样式 | F-08、F-09 |
| **项目** | 项目 → 任务 → 子任务树；行内展开进展时间线；拖拽排序（未决项 D2 在此定：**优先指针事件，不依赖 HTML5 DnD 的怪异行为**） | F-06、F-07 |
| **日志** | 日期选择器（默认今天）+ 自动汇总区（只读，与手写正文视觉区分）+ 手工正文编辑 + 保存 | F-16、F-17 |

补充：顶部放一个全局搜索框（F-11），命中后能跳到对应对象。

### A4 临时"热键"（可选，避免步 B 之前太难受）

用 Windows 桌面快捷方式 + `.cmd` 包装脚本，做到"双击图标即出现快记输入框"。
**这不是全局热键**（不能在任何程序里一按就出），只是过渡手段，**步 B 完成后立即废弃**。

### A5 顺手修一个 CLI 的现实问题

当前 `--data` 的默认值 `data` 是**相对当前工作目录**的。从桌面快捷方式或别的目录调用时，
会认不出数据库。应改为基于**脚本自身位置**推导项目根目录。这是步 A 必须带上的一处修正。

### A 的完成判据

- 能用界面完成：快记 → 收件箱分类 → 建项目 → 加子任务 → 推进 → 完成 → 写日志 → 搜索
- 全程不碰终端
- 全部既有测试仍然通过（证明内核未被界面污染）

## 4. 步 B · 桌面壳与全局热键（M1 前半）

**目标**：`Ctrl+Alt+Space` 在任何程序里按下去，快记窗立刻出现；输入完窗口消失，**原来的编辑位置不丢**。

### B0 前置：安装工具链（约 2–3GB，10–20 分钟）

| 要装 | 用途 | 说明 |
| --- | --- | --- |
| **Rust 工具链**（rustup，`x86_64-pc-windows-msvc`） | Tauri 的内核 | https://rustup.rs |
| **MSVC 生成工具**（VS 2022 Build Tools，含 C++ 工作负载 + Windows SDK） | Rust 在 Windows 的链接器 | 缺了会报 `link.exe not found` |
| WebView2 | 界面渲染引擎 | ✅ 已装（153.0.4234.48），无需处理 |

> 这一步**必须在你本机手动完成**（需要管理员权限，我无法代劳）。
> 装完告诉我，我先写一个最小 Tauri 窗口验证工具链通不通，再动真代码。

### B1 架构决策：Node 内核怎么进桌面壳（未决项 D3）

Tauri 壳是 Rust + WebView，而内核是 Node。有三种接法：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **B1-a 独立 Node 进程**（推荐首选） | Tauri 启动时拉起 `node src/ui/server.ts`，界面通过 HTTP 访问 | 内核**零改动**；崩溃互不影响；可直接复用现有服务层 | 多一个进程（约 40MB）；需要管进程生命周期与端口 |
| B1-b Node 侧车（sidecar） | 把 Node 运行时与内核打包成 Tauri sidecar | 分发时用户无需装 Node | 打包体积 +30MB，构建链更复杂 |
| B1-c 内核搬到 Rust | 用 Rust 重写数据层 | 单进程、最省内存 | **等于重写整个已验证的内核**，212 项测试全部作废 |

**决策**：先用 **B1-a**。理由是它让"M0 内核一行不改"这条纪律真正兑现，
且失败成本最低——如果进程管理太麻烦，再评估 B1-b。
这一步会在动工前用一个**最小可运行原型**验证（见 B2），而不是直接铺开。

### B2 最小原型先验证三件事

在写正式代码前，先做一个 50 行的 Tauri 窗口，验证：

1. Tauri 能否可靠启动并终止 Node 子进程（含异常退出后的清理）
2. **全局快捷键**在本机能否注册成功（`Ctrl+Alt+Space` 是否被其他软件占用）
3. 无边框置顶窗口的**呼出延迟**实测值（对应 ≤150ms 指标）

三项都通过，才继续 B3。

### B3 正式实现

| 项 | 要求 | 对应需求 |
| --- | --- | --- |
| **全局快捷键** | 默认 `Ctrl+Alt+Space`，可配置；注册冲突时**明确提示**而不是静默失效 | F-01、F-05 |
| **快记窗** | 无边框、置顶、居中偏上；打开即聚焦；`Enter` 保存并关闭；不抢走原窗口焦点 | F-01、F-03、§6.1 |
| **主窗口** | 复用步 A 的四页签（同一套静态资源，不重写） | F-06~F-17 |
| **单实例** | 重复启动时唤起已有窗口，不新开进程 | 避免多进程写库 |
| **冷启动** | 到可登记 ≤ 2s | 需求 §8 |

### B 的完成判据

在任意程序里按 `Ctrl+Alt+Space` → 输入 → `Enter` → 窗口消失且**原程序光标位置不变**，
端到端 ≤ 500ms。这一条通过，就可以开始"初步体验"了。

## 6. 步 D · 初步体验（验收）

到这里你才有资格判断"顺不顺手"。按需求 §6 的五条契约逐条实测：

| 契约 | 怎么验证 |
| --- | --- |
| 浮窗不抢焦点 | 在 Word/VSCode 里打字 → 热键 → 记一句 → 继续打字，光标位置是否还在原处 |
| 默认值正确 | 全程不选分类、不设时间，直接 `Enter`，是否都能存下 |
| 不存在保存失败 | 拔网线、锁库文件、强杀进程后重启，逐项检查记录是否还在 |
| 解析只是建议 | 输入一句含"下周三"的话，看标签是否正确、能否直接保存 |
| 收件箱不催我 | 攒 20 条放三天，看它是否只是显示数字而不打扰 |

**M0 的真正验收**：连续 3 天真实使用，不丢任何一条记录。
**M1 的验收**：一周内不需要主动"想起打开它"。

## 8. 风险与依赖

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **Rust + MSVC 安装失败或耗时过长**（步 B 的唯一硬前置） | 全局热键做不出来，只能停在步 A | 步 A 全部完成后先验证工具链，再动 B 的代码；期间界面已可用，不算停滞 |
| `Ctrl+Alt+Space` 被其他软件占用 | 热键注册失败 | B2 原型先实测；失败就换组合并在设置里暴露 |
| Node 子进程生命周期难管（崩溃残留、僵尸进程） | 常驻不可靠 | B2 原型专门验证；必要时退到 B1-b sidecar |
| 浏览器窗口无法真正"不抢焦点"（步 A 阶段） | 步 A 的快记体验打折 | 这是已知限制，**步 B 才真正解决**；不在步 A 硬凑 |
| 界面代码侵入内核 | 分层纪律被破坏，M1 换壳要重写 | 步 A 的完成判据里明确要求"内核一行不改、全部旧测试仍通过" |

## 9. 建议的执行顺序与检查点

| 顺序 | 工作 | 检查点（停下来给你看的东西） |

在 B 之前改的成本远低于在 Tauri 里改。
